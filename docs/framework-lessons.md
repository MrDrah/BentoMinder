# Framework lessons (app-boilerplate), observed while building BentoMinder

> Reusable lessons about the **framework**, kept apart from BentoMinder-specific issues (those go in `CATCH-UP.md` §6 and the decision log). Nothing here is fixed by editing the boilerplate from this project. Each lesson is a candidate for a framework release, raised with the product owner.

| # | Date | Area | What happened | Impact | Suggested framework change |
|---|------|------|---------------|--------|----------------------------|
| FL-01 | 2026-10-24 | Scaffold / sessions | The kick-off was started from a Claude Code session opened in another project (Cocktail Cabinet). The scaffold worked, but that session's hooks, permissions and session-start usage snapshot belonged to the other project until the session was moved into the new folder. Sub-agents dispatched in the first turn had their transcripts filed under the other project. | Token usage for the kick-off turn is attributed to the wrong project; BentoMinder's evidence package will under-count it. | README "Start a new project" should say: open a **new** session in the new folder before kick-off; `new-project.mjs` could print a warning when run from inside another framework project. `evidence.mjs usage` could accept an explicit transcript to import with a project tag. |
| FL-02 | 2026-10-24 | Preflight | A new local-only project (PO: no push without approval) fails preflight on "no origin remote", and preflight is in both gate stages. | The dev gate is red by design until a remote exists. | Make `requireRemote` default to `false` until the PO approves a remote, or downgrade it to WARN with a recorded reason. |
| FL-03 | 2026-10-24 | Git identity | Preflight warned "no git identity": the identity on this machine is repo-local in the other project, not global, and the framework forbids global git config. | Manual step: identity copied into the new repo's local config. | `new-project.mjs` could offer to copy the identity from the framework repo's local config, or print the exact local command. |
| FL-04 | 2026-10-24 | Kick-off order | `CLAUDE.md` §2 says to get the PO's yes on the BR table before dispatching any agent. This PO asked for requirements, architecture and design proposals *before* approving anything. | Orchestrator relaxed the rule for proposal-only work and logged it. | Distinguish "proposal" dispatches (allowed before BR approval, docs only) from build dispatches in the kick-off rule. |
| FL-05 | 2026-10-24 | Stack assumptions | The framework's defaults assume a static site with no server (MVP) and a researched-content app. BentoMinder needs a server-side AI adapter in the MVP, user data stored locally, and a native (Capacitor) target later. | The `backend-integration` skill is labelled v1, but this MVP needs part of it from day one. | Let the plan pick the modules per milestone ("MVP needs: AI integration seam") instead of tying backend work to v1. Add a mobile/Capacitor note to the implementation skill. |
| FL-06 | 2026-10-24 | Evidence event log | `evidence.mjs event` correctly refused a summary containing a local path. | None (good control); noted so the count of rejected events is explained. | — |
| FL-07 | 2026-10-24 | Overlap audit | `validate.mjs overlap` tokenises with `/[a-z0-9']+/` (verified, line 299). Japanese text produces no tokens, so copied Japanese recipe prose would PASS. Reported by the developer agent, confirmed by the Orchestrator. | The "own words" rule is unenforced for Japanese content, which is BentoMinder's primary language. | Tokenise CJK as character n-grams (e.g. runs of ≥ 20 kana/kanji) in addition to Latin words. Until then: verifier spot-checks Japanese text manually. |
| FL-08 | 2026-10-24 | diff-guard | Four content agents shared one checkout, as `CLAUDE.md` §2 allows. `diff-guard --task <t>` compares against the shared baseline, so each task FAILs on the other agents' files. | Per-task attribution is impossible; the Orchestrator has to check each report's file list by hand against the union. | Let diff-guard take `--others <task,…>` to exclude files on concurrent tasks' allow-lists, or give each content agent a worktree too. |
| FL-09 | 2026-10-24 | task-start baseline | A second round on the same files (H1 fix round) before committing: `task-start` warns that the 27 already-changed files "will be ignored by diff-guard", so the exact files the round edits are unguarded. Committing first would fix it, but the hard rule is "commit only when the PO asks". | diff-guard is blind for iterative rounds on uncommitted work; the Orchestrator falls back to a manual union check. | Baseline content hashes of dirty files (not only the commit), or allow local checkpoint commits on a work branch as an approved part of the loop. |
| FL-10 | 2026-10-24 | evidence.mjs event | `event task-end` requires `--outcome`, but the skill's table doesn't say so and diff-guard only logs task-end automatically when run per task (not with a manual union check). | Three events rejected on the first try. | Document the required options per event type in the skill table, or default the outcome. |
| FL-11 | 2026-10-24 | task-start / diff-guard | `--allow` takes one glob per flag; a comma-separated string is silently accepted as a single glob that matches nothing, and task-start echoes it back as if it were a list. diff-guard then FAILs everything and auto-logs a `task-end` **failure** event, which can't be removed from the append-only log. (This also explains part of FL-08: those runs would have failed even without shared checkouts.) | Every diff-guard run in the kick-off and H1 rounds was meaningless; the Orchestrator's manual union checks were the real control. False failure events in the log, corrected by a later event. Orchestrator error, enabled by the tool's silent acceptance. | Split `--allow` values on commas or reject a glob containing a comma; print the parsed list one per line. |
| FL-12 | 2026-10-24 | Secrets deny rule | The `permissions.deny` / guard rule for `.env*` also blocks reading and writing the example env file, which the framework's own template ships, `.gitignore` explicitly un-ignores, and the guard's own error message tells the agent to use. The guard even blocks a shell command that merely *mentions* the file name in a text argument. The developer couldn't complete its task list; the Orchestrator refused to write the file on the agent's behalf (that would launder the denial). | Manual step for the PO; one Orchestrator command blocked on a false positive. | Deny `.env` and `.env.*` except the example file; match on file access, not on text mentions. |
| FL-13 | 2026-10-24 | Worktrees on Windows | The developer's gate was green in its worktree (files written with LF) but red on main after the merge: `core.autocrlf=true` checked the files out with CRLF, and a CRLF shebang line broke Vitest's import of `scripts/*.mjs`. The scaffold ships no `.gitattributes`. | "Green in the worktree" did not mean green after integration; re-running the gate on main caught it. Orchestrator added `.gitattributes` (`* text=auto eol=lf`). | Ship a `.gitattributes` with `eol=lf` in the project template; tell the Orchestrator to always re-run the gate after merging a worktree (the loop says "re-run the gate", but not "on the integrated checkout"). |
